You are formalizing the structured relationships between entities in a freshly-generated D&D 5e world. Stages 2 and 3 produced regions, factions, locations, and NPCs along with prose that often describes how those entities relate. Your job is to extract those relationships into a strict structured form so downstream systems can reason about them mechanically.

## Your Task

Produce a JSON object with three arrays:

1. **`relationships`** — between 5 and 80 entries. Each entry has:
   - **`from`** — the source entity's UUID from the inventory above, OR a placeholder ID for an entity declared in `new_entity_declarations` below.
   - **`to`** — the target entity's UUID from the inventory above, OR a placeholder ID for an entity declared in `new_entity_declarations` below.
   - **`relationship`** — exactly one of the closed set below. If a connection doesn't fit any of these labels cleanly, map it to the closest fit or skip it; do NOT invent new labels.
   - **`description`** — 10–600 characters of free text describing the relationship. Concrete, specific, grounded in the prose above.

   Closed set of `relationship` values:
   `serves`, `opposed_to`, `allied_with`, `rival_of`, `controls`, `family_member`, `mentors`, `employed_by`, `located_in`, `leads`, `member_of`, `rules`, `former_servant_of`, `pursues`, `protects`, `betrayed_by`.

2. **`hierarchy_stragglers`** — up to 20 entries (may be empty). Each entry has `parent_entity_id` and `child_entity_id` (both UUIDs from the inventory). Use this ONLY for parent-child location containment that stage 3 missed — for example, a settlement that should be inside a region but wasn't linked. Do NOT use this for ordinary relationships; those go in `relationships`.

3. **`new_entity_declarations`** — up to 15 entries (may be empty). Use this when the prose above names a faction, location, or NPC that is structurally important but does NOT appear in the inventory. See the next section for the mechanism.

## Declaring missing entities (phantom references)

Read the prose carefully. When it names a faction, location, or NPC that is NOT in the inventory above — call this a "phantom reference" — you MUST declare it here rather than skip the relationship. The system will create the real entity in a subsequent step.

Examples of phantom references you should declare:
- A region's prose names a rival hunting band that has no entity row.
- A faction's prose names an institution it answers to that has no entity row.
- A location's prose names a parent realm or a sister settlement that has no entity row.

To declare a phantom:
1. Add an entry to `new_entity_declarations` with a placeholder ID of the form `new-001`, `new-002`, etc., the entity's intended name (as named in the prose), and its type (`faction`, `location`, or `npc`).
2. Use that placeholder ID in `relationships` for any relationship that points at the phantom.

Worked example. If the inventory contains The Long Vigil (UUID `aaaa-...`) and the prose says The Long Vigil contests territory with the Ironjaw — but no Ironjaw entity exists in the inventory — the correct output is:

{
  "relationships": [
    {
      "from": "aaaa-...",
      "to": "new-001",
      "relationship": "rival_of",
      "description": "The Long Vigil and the Ironjaw contest territory in the Bone Reach."
    }
  ],
  "hierarchy_stragglers": [],
  "new_entity_declarations": [
    { "placeholder_id": "new-001", "name": "The Ironjaw", "entity_type": "faction" }
  ]
}

Rules:
- Declare a phantom ONLY when the entity is named explicitly in prose AND is needed as a relationship endpoint. Don't invent entities to pad the world.
- Every placeholder ID used in `relationships.from` or `relationships.to` MUST have a matching `new_entity_declarations` entry. Orphan placeholders are silently dropped.
- Pick the simplest placeholder IDs in order: `new-001`, `new-002`, etc. Don't skip numbers.

## Guidance

- Read the prose carefully. Many relationships are implicit (rivalries, vassalages, employment, family ties, geographic containment). Extract the implicit ones along with the explicit ones.
- Favor specific connections (this NPC betrayed this faction) over generic ones (this NPC is connected to politics). Generic edges are not useful downstream.
- Emit between 5 and 80 relationships. Quality over quantity, but a typical world produces 10–30.
- You are free to emit multiple relationships between the same pair of entities if they hold multiple distinct relations (e.g. `allied_with` AND `family_member`).
- Do not narrate. Each `description` should read like a structured note, not a story paragraph.

Respond with ONLY the JSON object. No markdown fences, no commentary.
