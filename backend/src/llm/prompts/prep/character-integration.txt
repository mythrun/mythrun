## What to produce

For each character in the party, emit a structured row with:

- A PC `entity` row (entity_type='pc') with `name` and `proseKernel` (a 1-2 paragraph prose summary of who this character is in this world).
- A `facts` array (3-8 starting facts about the PC: hometown, profession, what brings them to the starting situation, anything else load-bearing). Each fact may reference a world entity via `aboutEntityId` (UUID) or null for self-facts. Facts MAY NOT reference other PCs — cross-PC content goes through `relationships[]`.
- A `relationships` array — edges to NPCs, factions, locations, and OTHER PCs in this party.

The party MUST be coherent. Where the owner's notes specify a relationship between two PCs, reflect it. PC↔PC relationships should be emitted ONCE per pair (the worker mirrors the symmetric edge); use the target PC's `userId` from the party block above as `targetUserId`.

You may add facts to existing world entities ONLY when integrating a PC requires it (e.g., this PC knew NPC X from their backstory, so NPC X gets a corresponding fact). Use the `newFacts` array for these. Do NOT invent new NPCs, locations, or factions — those exist already in the world dump. Reference existing entities by their UUID.
