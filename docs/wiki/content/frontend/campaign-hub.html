Campaign hub

The player's home base between sessions: a quiet shelf of their campaigns, each a small book-cover card carrying its world's colour identity, with a clear path to make a new one. The hub is the first real screen the app renders — a full-stack vertical from the /mine payload to the cover art.

How it fits together

HomeRoute owns a <Suspense> boundary; the data-consuming inner component calls useMyCampaigns — a client-core suspense query over GET /api/campaigns/mine — so it only renders once the payload resolves. A screen reaches the backend only through a client-core hook, never raw fetch; the loading spinner and the route-level error boundary handle the other two states. With zero campaigns the hub shows a first-run empty shelf; otherwise it renders the responsive body.

The cover card — a book cover

Each campaign is a portrait CampaignCard, composed entirely from mythrunUI primitives — no ad-hoc UI. A CoverCard carries the world's two-colour identity as a full-bleed CoverDither band (~40% of the card), an ink seam, then a body: a serif title and an italic world · creator line at the top, and a mono "imprint" pinned to the foot — the party seals (square Avatar tiles) over the record/state line. The whole card is one link to the campaign's detail.

Status is text, never a dot — the paper register forbids status dots, badges, and chips. A campaign's state is conveyed by the mono ledger line plus the implicit party seals, and nothing else. The line is derived once by cardPhaseLine from the payload's cardPhase: "shaping your world", "make your character", "waiting for players", or, once played, the "N sessions · 2 days ago" record — the only place the hub formats a relative time (mechanical Intl.RelativeTimeFormat, locale-aware). The card and the mobile row render this exact string, so the logic lives in one shared module.
The cover link is unstyled — mythrunUI's Link tints its whole subtree with the accent foreground, so a plain link would render the cover's title, world, and state in link-accent instead of ink. The unstyled variant drops the accent paint while keeping the accessibility focus ring, so a whole-card link still reads in the quiet paper-ink register. When a world has no colour pick yet (worldColors === null), the cover shows CoverDither's muted paper ghost band rather than borrowing a fake chromatic identity.

Grid on the wall, index in the hand

The card and the mobile row are visually distinct layouts — a cover card versus a table-of-contents line — so CampaignHubBody is a breakpoint switch, not a reflow. It uses the Show primitive (the one place a raw breakpoint class is legal, so the screen stays ad-hoc-UI-free): at and above sm, a fluid Grid of cover cards; below it, a compact Stack of hairline-divided index rows.

A fluid shelf, not a fixed column count — the grid uses auto-fill at the card's ~230px cover width, packing as many covers per row as comfortably fit, then wrapping. The shelf grows with the viewport instead of snapping to 1/2/3 columns. This needed the design system's new px minColumnPx track, since the token space scale caps well below a card width. Each mobile CampaignIndexRow is a small self-sized world swatch plus three truncating text lines beside it, so every row is exactly one line tall — uniform height by truncation, not a hard-coded pixel height.

The empty shelf

With no campaigns the hub centers a single "Unwritten" cover: a Card frame="dashed" (the design system's new dashed variant, reading as an outline waiting to be filled) wrapping a muted paper ghost band — the same ghost a still-generating world shows — over an evocative one-line invitation and a "Create a campaign" CTA that routes into the campaign-creation flow. The card click and the CTA both point at real routes.

The header credits

The always-present app frame carries the live session-credit balance. HeaderCredits reads it through the useBalance suspense hook and renders a terse mono number, but because it is a suspense query in a frame that must paint immediately, it wraps itself in its own <Suspense> and a local error boundary.

The credits slot degrades alone — a slow or failed balance fetch must never tear down the whole authed shell through the router error boundary. So the slot loads behind a small spinner and renders nothing on failure; the "+" buy affordance beside it sits outside that boundary, so a player can still act even if the number didn't load. The buy "+" and the settings gear route to an interim /settings until the dedicated buy flow ships; the frame's logomark and display-name slots remain chrome placeholders for now. The card's click target is a thin interim campaign-detail stub — a real route, not a dead click — with the modal/sheet body left to a later ticket.

Integration points

The hub consumes the campaign hub payload (useMyCampaigns) and the balance endpoint (useBalance), both through the client-core data layer. Every visible piece — the CoverCard, CoverDither, Show, the dashed Card, the AvatarGroup seals — is a mythrunUI primitive. The cover colours come from the world colour identity.
