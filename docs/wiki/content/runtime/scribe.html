Scribe

The post-turn reconciler — off the hot path. After each DM turn it turns the Fast Thinker's improvisation into durable in-session canon without breaking secrets: it appends the turn's proposed facts to an ephemeral session working set the FT can read next turn, and runs a per-turn Haiku secret tripwire over the player-facing prose. The tripwire returns a severity, and the severity picks the remedy: an actual reveal gets an Opus-authored secret-preserving retcon the DM delivers openly on a player-less correction turn; an NPC merely acting in character gets a silent nudge to the Slow Thinker instead. The secret sd_playbook is read only on the secret side; the FT sees working-set content only through the Slow-Thinker-vet relay.

How it fits together

An AI DM that never remembers what it improvised is a worse DM than a human one. When the Fast Thinker names a new NPC, invents a tavern, or has a character recall a fact, that has to become canon for the rest of the session — findable on a later turn, consistent across players. But the FT runs under enforced ignorance: it has no plot, no secrets, no way to know whether what it just said collides with what the world hides. The Scribe is the tier that closes that loop. It runs after the turn, in its own background job, and does two jobs at once: it captures the turn's new facts into a working set the FT can recall, and it guards the secret boundary the FT can't see.

Why post-turn, off the hot path — both Scribe jobs are retrospective: capture reads what the FT actually wrote, and the tripwire checks the prose that already shipped. Neither needs to block the player's stream. So the Scribe is a seventh BullMQ worker the turn worker feeds on its flushed-success path — the same post-hoc shape as the Slow Thinker. A correction lands one turn late, which is fine: the DM saying "a moment — let me correct something" a beat later reads as natural table talk, not a glitch. Player-visible time-to-first-token is unaffected.

Four inputs ride the job. The Fast Thinker appends a lightweight fact-delta after its prose (the new named things it introduced this turn). The lookup tools' ST-vet records each injection (a fact it relayed or invented mid-turn) into a per-turn sink. The turn's resolved skill checks ride along — roll, tier, and the outcome constraint the FT wrote under — which are public by construction (the outcome table is generated FT-side under enforced ignorance, and the constraint already streamed to the players on the skill_check frame). And the FT's whole player-facing prose is the tripwire's input. The SessionController assembles all of it into one ScribeJobPayload and the worker enqueues it once per flushed turn.

The fact-delta: the FT's public-by-construction proposal

The FT emits its proposed facts itself, as a structured tail after the prose. The ft-system.txt prompt teaches it: after the player-facing narration, and only after it, it may append a newline-anchored [[WORLD_DELTA]] marker followed by one line of JSON listing the new named entities, facts, and relationships it introduced. The WorldDeltaSchema is flat — { subject, content, kind } per item, prose floors but no length caps — and it carries no tier field: the FT has no secrets, so every delta is public-by-construction, and the Scribe stamps tier: 'known' downstream.

The delta is stripped from both sinks by a dual-sink delimiter guard — the [[WORLD_DELTA]] section is internal machinery; a player must never see it and it must never enter the durable transcript (where the FT would re-read it as if it were prose). The FT's consume loop routes its text-delta substream through a stateful char-by-char filter that sits between the stream and both downstream sinks — the live player emit AND the assembler that builds the persisted message. Only the pre-delimiter prose reaches either; everything from the newline-anchored literal onward is suppressed and captured for parsing at turn end. Guarding only one sink would defeat the point, so the guard feeds a single callback wired to both. A failed parse fail-softs: the prose already shipped, so a malformed delta is dropped with a warn, never a thrown turn.
The newline anchor is load-bearing — the guard matches the literal \n[[WORLD_DELTA]], leading newline included, via a KMP walk that re-anchors on a diverging character without re-feeding any. A bare [ mid-sentence can never arm it, so ordinary prose that happens to contain a bracket flushes straight through. A partial match pending at a delta boundary or a tool-call boundary is held back and coalesced once it resolves, so the filter never splits a clean run into per-character emissions and never strands a half-matched prefix.

The working set: ephemeral in-session canon

The captured facts land in the working set — proposed narrative facts produced during a live session that have not yet been reconciled into the durable world store. It is in-session only, keyed by campaign, backed by a single Redis list (session:{campaignId}:workingset) whose TTL matches the rest of the session's Redis state (~2h). Each item is a WorkingSetProposal — kind, content, subject, tier, provenance, and a source tag (ft_delta / st_injection / retcon) — plus an id, the turn id, and a 512-dim Voyage document embedding stamped on append. The Scribe embeds the turn's proposals (the same input_type: 'document' the canon write path uses, for parity) and RPUSHes them.

Append-only on the hot path; eviction only under the lock — concurrent turns must never lose a fact to a load-blob / mutate / SET race (the failure mode a JSON-blob key would have). So the append is a single atomic RPUSH of all the turn's items — concurrent appends interleave at the command boundary, never clobbering. Eviction is the one rewrite path (DEL + RPUSH) and is deliberately non-atomic; it is safe only because it runs from the post-turn Scribe job under the per-session lock, where no concurrent append can interleave. The cap is 200 items, and eviction drops only the oldest public (ft_delta) items — never an st_injection or a retcon, and always keeping the newest public item so a turn's just-proposed fact survives its own eviction pass.
The working set never holds a raw secret — this is the invariant the whole tier is built around. The FT deltas are public by construction. The ST injections are the already-vetted relay text the lookup vet produced — secret-free by the time the orchestrator sees it. And the retcon item carries only the secret-free correction prose plus an opaque secret handle — never the false thing it corrects (which names the secret by construction). So even though the working set is the FT's read-after-write memory, there is nothing in it the FT isn't allowed to know.

The read-after-write: working set ∪ canon

A fact invented on turn 5 has to be recallable on turn 9. The FT's lookup tools make that work by reading the working set unioned with canon. When search_lore runs, it loads the turn's working set and cosine-ranks each item's embedding against the same query vector searchLore already embedded — no second Voyage call — then merges the top matches into the canon LoreHit[] before rendering the tier-annotated block. The graph walks (characters_known_to, faction_tree) flat-append the turn's working-set entity and relationship items the same way. The merged block funnels to the ST-vet exactly as canon does.

The FT reads the working set only through the ST-vet relay — never as a context field — the read-merge happens inside the lookup tool's resolver closure, whose output goes to the Slow-Thinker vet, not to the FT directly. The FT's context type carries a workingSet field, but the turn worker pins it to [] permanently: the working set reaches the FT only down the gated lookup path, where the over-pull/tier-gate boundary applies to a working-set item exactly as it does to a canon row. A secret-tier working-set item (an ST injection the vet tiered as secret) is gated by the vet, never filtered out at the merge — so the gate stays the single tier-safety boundary and a future tool that reads FtTurnContext.workingSet still sees nothing.
An NPC's claim never elevates to objective truth — a working-set item carries provenance. A DM-channel relay is objective (true in-world); an NPC-channel relay is attributed (the NPC said it — it may be a lie, rumor, or mistake), tagged with the NPC's entity id and name. When the merge renders an attributed item it prefixes a [claim by {npc}] annotation alongside the [tier=…] tag, so neither the ST-vet nor the prose downstream ever surfaces an NPC's claim as ground truth.
A third provenance: dice_outcome, and why it exists — when a turn resolved a passing skill check, the facts it asserted were at least partly licensed by the system's own outcome table. Those proposals are stamped dice_outcome with the tier that earned them (highest passing tier wins; a turn with only failed checks or none stays objective). This is canonize-on-grant: a reward the system granted under a success is canon the moment it lands. If it collides with scripted prep material, the world conforms to play — the collision steers future turns down the soft ST path; it never erases the grant. The stamp is deliberately coarse: deciding which fact the dice earned would be local intelligence over prose, so the reconciler sees the provenance and makes the judgment.

The secret tripwire: the per-turn breach detector

The other half of the Scribe job is the safety check. secret-tripwire.ts is a cheap Haiku generateObject call that reads the FT's player-facing prose against the session's core secrets and returns an opaque control signal — { severity, confidence, secretRef }, where secretRef is a handle like [SECRET-1], never secret-derived prose. There is deliberately no free-text why field and no .refine on the schema: the first would carry the secret, and the second lets the repair chain author a "valid" tree and defeat the gate.

The tripwire fires on every turn, so its prompt was reordered to be cacheable: the instruction head, the secrets, the public context, and the consistency context now sit above a cache breakpoint, with the one part that changes each turn — the prose being checked — below it. Nothing was rewritten; the sections were permuted, and the handful of instructions that referred to material "below" still point at the right place. Its stable span is 9,514 tokens, comfortably above Haiku's 4,096-token minimum, and the per-turn cost of the gate and tripwire together dropped 64%.

Reordering a classifier's prompt is a behavioral change until proven otherwise — this template decides whether a secret leaked, and models are sensitive to what they read first. So the reorder shipped behind a parity gate rather than a code review: a byte-level proof that the new template is a pure permutation of the old, a verdict-parity harness running both orderings through the real assembly path across the severity lattice (grounded, dice-grounded, consistency, seeded reveal) and diffing outcomes, and the existing constructed-state scenarios re-run unchanged. A live run afterwards confirmed the distribution held. The offline harness deliberately cannot prove Haiku is order-blind — only that our assembly is — which is why the live confirmation was treated as load-bearing rather than a formality.

Severity, not a boolean

The verdict used to be breached: true | false. That bit conflated two very different things, because the FT writes blind: a "hit" is either an accidental hard reveal or improvised colour that merely rhymes with a hidden truth. Both routed to the same open, player-facing correction. So an NPC whose gaze drifted to a door — good DMing, and exactly what a hidden agenda should look like from outside — earned a public "actually, his eyes were just wandering", which confused the player and advertised the secret. The Streisand retcon. The verdict is now a severity:

  • hard_reveal — the prose states a secret, or a player could only conclude its actual content from it. This alone warrants a player-facing correction.
  • soft_consistency — an NPC acts in line with a hidden agenda (a gaze, a mood, guarding a door) without stating or necessarily implying the secret. Good DMing, not a leak.
  • none — no meaningful relation to any secret.
Confidence survives as observability, not as a gate — routing is severity's job now; the old TRIPWIRE_ESCALATE_CONFIDENCE_FLOOR is gone. The recall bias it existed to express lives inside the severity call instead: any hard_reveal fires the correction regardless of how confident the model claims to be, because a suspected live leak is corrected rather than waved through. What changed is that a low-confidence hit no longer reaches the disruptive path merely by virtue of being a hit — the severity split is what makes the remedy proportionate.

The grounding floor

A tripwire that only ever sees prose and secrets will fire on prose the system itself licensed. Two inputs stop that. The first is the public briefing — the same enforced-ignorance-safe ft_context the FT reads. A detail grounded there was explicitly handed to the narrator, so it is definitionally not a breach even when it is thematically consistent with a secret. (The incident that forced this: an NPC watching a door the briefing already said he watches.) The second is the turn's resolved skill-check outcomes — the deterministic roll plus the Haiku-generated outcome constraint the FT wrote under. Content the system granted through a resolved roll is likewise not a breach.

Reading a public column is not widening the secret surface — the Scribe's narrow ScribeRepo now returns ftContext alongside sdPlaybook. That looks like a boundary loosening and is the opposite: ft_context is the public artifact, already in the FT's own hands every turn, and it enters here only to make the tripwire fire less. An empty briefing degrades gracefully — grounding simply rescues nothing that turn — rather than failing the job.

Splitting the playbook

The other half of the false-positive problem was the input shape. The whole sd_playbook used to ride a single [SECRET-1] handle, so "the prose contradicts an encounter script" and "the prose revealed a secret" were literally indistinguishable in the verdict — which is how a dice-earned reward got openly retconned. splitPlaybook now parses the prep template's section seams: only the actual secret sections (NPC secrets and the revelation list) get per-secret [SECRET-n] handles, and everything else — session goals, knowledge bounds, encounter scripts, pacing, hooks — becomes consistency material, which the tripwire may route to the soft path only.

Structural parsing of a template we author is ZFC-legal — this is not intelligence about prose; it is splitting a markdown document on headings we wrote ourselves, matched as case-insensitive prefixes so minor prep drift still classifies. When no secret section is recognized at all the split falls back to the old whole-playbook lump and logs a warn: over- protective rather than under-protective, and visible rather than silent.

The remedy, routed

none logs clean and returns. soft_consistency gets the silent remedy: no player-facing correction at all, just an st-evaluation enqueue so the secret-aware Opus director can decide for itself whether to steer future turns through its standing directive. Only hard_reveal reaches the open retcon below — and only when it cites one of the emitted handles.

The hard-reveal handle gate — an open, player-facing correction is licensed only when the tripwire named a real [SECRET-n] from this playbook. A hard verdict with a null, [CONSISTENCY], or hallucinated ref means no listed core secret was actually named, so it routes to the silent path instead. This is structural validation of an opaque control signal — the same class of check as a schema validation — and it is the backstop that keeps a scripted-canon collision off the disruptive path even if the severity call itself gets it wrong.
The soft path carries strictly less back than the retcon path — the ST signal is a bare enqueue: campaign and session ids, nothing secret-derived, no text. It is dedup-collapsed per campaign by the st-eval queue's no-TTL dedup, so a scene full of in-character NPC beats cannot spam Opus, and it is total — an enqueue failure logs and returns, because steering is an enhancement and the ST's own five-turn oversight floor is the backstop. The turn already shipped clean; nothing is being repaired here, only aimed.

Every verdict is durable

Each verdict writes one row to tripwire_verdicts (migration 037): campaign, session, turn, severity, confidence, handle. Forensics on a live incident previously had to infer a firing breach from two incidental "skipping re-author" log lines; the table makes the whole series queryable per turn. The insert has its own try/catch — verdict persistence is observability, and this job is total, so a Postgres hiccup must never skip the routing.

The handle is sanitized before it is stored — secret_ref is a free string on the wire, and the schema's handle-only contract is a promise the model makes, not one the database can rely on. So a ref that is not a recognized [SECRET-n] or [CONSISTENCY] collapses to [UNRECOGNIZED] before insert. A durable row must not depend on the model honouring a contract — the same rule that keeps a corrected-field echo out of shared storage.
A disarmed tripwire is worse than an error — so an empty playbook fails loud — the Scribe resolves the sd_playbook for the campaign's active session through a dedicated narrow ScribeRepo surface (it mirrors the Slow Thinker's StEvalRepo and the lookup vet's repo — never a widening of the FT-side turn-worker repo). If the playbook is absent or empty, the job logs a loud scribe_tripwire_misconfigured error and returns rather than silently skipping the check: a session running with the tripwire quietly off is the worst outcome, so it is made loud.

The retcon: a secret-preserving correction on a player-less turn

On a hard_reveal that cited a real handle, retcon-author.ts writes the fix. It is an Opus call — the same tier as the narrative director — because the judgment is the same: it reasons over the secret to author a correction Z that removes the contradiction without revealing the secret, paraphrased or implied. Its retconText is the player-facing correction prose, surfaced verbatim. The Scribe then delivers it through a player-less correction turn: it enqueues a normal session-turn job with trigger.kind: 'correction', empty trigger messages, and the correctionText set to Z.

Why the retcon rides a player-less correction turn — the correction has to be spoken by the DM in the same voice, streamed through the same wire, persisted in the same transcript as any other DM turn. Reusing the turn path gets all of that for free instead of building a parallel delivery channel. The turn worker recognizes the correction kind: it does not consume the one-shot/standing direction slots (burning a sanctioned reveal on a correction would be wrong) and instead sets the worker-injected Z as a distinct [[DM CORRECTION: …]] marker — the one explicit exception to the FT's silent-consume rule. The FT prompt teaches it to deliver that marker openly: "earlier I said X; correction — it's actually …", terse, in-fiction, then hands the floor back. A correction turn also does not advance the responded-seq watermark (it consumed no player message) and does not itself enqueue a Scribe job — running the tripwire over an already-vetted secret-free correction is wasted spend and risks a retcon loop.
The retcon item stores Z and a handle — never the false thing it corrects — the Scribe appends a retcon-source item to the working set so the correction is durable in-session, but it carries only the secret-free Z and the opaque secretRef handle. The author's supersededContent — the false statement being corrected — names the secret by construction (the breach prose stated it openly), so it is deliberately NOT persisted: storing it would put a raw core secret into ephemeral session state. The real-LLM smoke caught exactly this leak, which the mocked test had masked with a clean spy value. Supersession, when the durable-canon issue needs it, is tracked secret-free by id reference, never by raw prose.
Double-retcon guard — the tripwire can re-fire on the same secret while the first correction is still live in the working set (the breach prose is still in recent narration). The Scribe matches a live retcon item by its secretRef (stored in the item's subject field) and skips re-authoring — one correction per secret, not a loop.

Total by construction

The producer is the turn worker's post-turn finally phase, so the whole job is total: processScribeJob never throws out. A working-set append/evict failure logs and continues to the tripwire (the secret check is the load-bearing half). A tripwire call failure skips the breach check this turn and returns. A verdict-persist failure or a failed soft-path ST enqueue logs and continues — both are observability and steering, not correctness. An embed failure degrades to empty embeddings (the fact still appends, just unrankable until re-embedded) rather than dropping the turn's facts. A retcon-author repair attempt fail-softs — a repaired tree was re-authored by a different model and could re-author the safety-critical text, so the correction is skipped and re-fires next turn. Transient failures lean on BullMQ retry; the one loud error is the disarmed tripwire.

Operating this piece

Watch an invented fact survive to the next turn

  1. Bring up the data plane and both processes (pnpm db:up, pnpm dev, and pnpm --filter @mythrun/backend dev:worker — the worker hosts the Scribe worker). Start a session and fire a turn whose prose names a new NPC or place (the fire-turn dev route).
  2. After the turn flushes, confirm the working set grew: LRANGE session:{cId}:workingset 0 -1 on the realtime Redis shows the turn's ft_delta items (and any st_injection from a mid-turn lookup), each with a non-empty embedding.
  3. Fire a later turn whose narration would reasonably recall that thing and watch the FT's search_lore surface it — the read-merge funnels the working-set hit through the ST-vet alongside canon.

Exercise the tripwire and the retcon

  1. Run the gated real-LLM smoke: pnpm --filter @mythrun/backend smoke:scribe. It seeds a session with an sd_playbook core secret, drives a turn whose prose breaks it, and asserts the real Haiku tripwire fires, the real Opus retcon authors a secret-free Z, and a correction turn delivers it.
  2. On the worker log, a clean turn logs scribe: tripwire clean; no retcon; a hard_reveal logs hard_reveal breach → authoring open retcon with its handle and confidence, and (on a fresh secret) the enqueued correction. Grep the streamed correction prose against the playbook's secret strings to confirm zero verbatim leak.
  3. A turn that logs soft_consistency (NPC behavior consistent with a secret) — NO player correction took the silent path: expect an st-evaluation enqueue and no correction turn. A hard_reveal without a recognized secret handle warn means the handle gate rerouted a hard verdict to the same silent path — worth reading alongside the playbook split's no recognizable secret sections warn, which says the prep doc's headings drifted.
  4. For the full series rather than a single turn, query the durable verdicts: SELECT turn_id, severity, confidence, secret_ref FROM tripwire_verdicts WHERE session_id = '<id>' ORDER BY created_at.
  5. A scribe_tripwire_misconfigured error means the session's sd_playbook was empty or unresolvable — the tripwire ran disarmed-and-loud rather than silent. Verify the session prep produced a playbook.

Integration points

The Scribe is the post-turn capture-and-guard half of the session-turn pipeline: that worker assembles the job (enqueueScribeJob) on its flushed-success path and the Scribe worker — the seventh BullMQ worker in the worker process — runs it. Its tripwire and retcon-author call Haiku and Opus through the LLM client's generateObject; both set redactRawText because their raw output reasons over secrets, the same posture as the lookup vet. The working set feeds back into the Fast Thinker's lookup tools as their read-after-write source, and the retcon rides the turn worker's correction turn kind. The FT fact-delta and the lookup vet's injections are the two capture inputs; the boot-probed Voyage embedder it shares with the world-store retrieval substrate stamps the working-set vectors. The working set the Scribe builds is folded into the canonical world store by the end-of-session reconciliation when the session ends — this tier holds it in-session, and the tier and provenance it stamps on each item are what the reconciler's tier-floor and attribution policy enforce on commit.
