DNS

The Route 53 hosted zone for mythrun.com — Gmail preserved exactly, a wildcard ACM cert ready for any ALB or CloudFront that needs it, and a one-step path from registrar to Terraform-managed DNS.

How it fits together

The dns module lives in the shared workspace because the zone is cross-environment: staging and production subdomains (staging-api, api, apex, www) all resolve through the same authoritative nameservers, and one wildcard cert fronts all of them. The module creates the public hosted zone, replays the email record set from the pre-cutover Squarespace audit, and provisions a validated wildcard ACM certificate whose ARN is re-exported for per-env consumers.

Zone lives in shared/, not per-env — there is exactly one mythrun.com. Putting the zone in staging or production would either duplicate nameserver assignments (you can only delegate to one set) or force production to depend on staging state. Shared is the only placement that doesn't create a false hierarchy between envs.

The email record set

Google Workspace mail is load-bearing — it's Miklos's inbox. The cutover rule was replicate the Squarespace records exactly, verify against AWS nameservers before flipping the registrar, and swap NS only once resolution is green. Nine records carry the entire email surface: five MX rows (Google's four aspmx hosts at priorities 1/5/5/10/10), an apex TXT collapsing SPF and Google site-verification into one RRSET, a DMARC record at _dmarc, and a DKIM record at google._domainkey.

TTL 300, not Squarespace's 1800–14400 — a low TTL means a record-set mistake propagates its fix in five minutes instead of four hours. This is a one-time cost (slightly more resolver traffic) for a big operational win the first time something is wrong.

DKIM is the record with a wire-format quirk. A DNS TXT string is capped at 255 octets; DKIM public keys are ~256–400 chars, so the value has to be split into multiple character-strings. The AWS provider already wraps each records[] element in outer double-quotes before sending to Route 53, so the Terraform expression produces chunks joined by the literal " " sequence without its own outer quotes. After the provider wraps, Route 53 receives "chunk1" "chunk2" — a single TXT record composed of two character-strings, which is exactly the DKIM wire format.

Why this bit me — the first attempt wrapped the chunked output explicitly; Route 53 rejected it with InvalidCharacterString because the provider's outer wrap then produced ""chunk1" "chunk2"". The fix (dropping the explicit wrap) is three characters of Terraform, but reading the AWS provider's TXT-quoting behavior is the expensive part. Any future multi-string TXT record (long SPF, BIMI VMC) uses the same pattern.

Wildcard certificate

A single aws_acm_certificate covers the apex (mythrun.com) plus any one-label subdomain (*.mythrun.com). Two-label subdomains would need their own SANs — a non-concern at launch. Validation is DNS-01: ACM returns one CNAME record per unique parent domain, Terraform publishes it via for_each, and a aws_acm_certificate_validation waiter blocks downstream use until ACM flips the cert to ISSUED. The outputs re-export the waiter's certificate_arn, not the cert's raw ARN, so consumers can't accidentally attach an unvalidated cert to an ALB listener.

Validation runs after the NS swap, not before — ACM only starts polling the validation CNAME once Route 53 is globally authoritative for the zone, which happens when the registrar's NS records point at AWS. The operational consequence: the first apply either uses -target to provision everything except the validation waiter, cuts over, then runs a clean second apply; or accepts the waiter sitting in "Still creating…" for 5–30 minutes across the cutover. The module supports both.

Cross-environment consumption

Four outputs from the shared workspace are the contract with per-env workspaces: dns_zone_id, dns_zone_name, name_servers (informational after the cutover), and wildcard_cert_arn. Per-env workspaces read them via data.terraform_remote_state.shared and use them to build A-alias records for their ALB targets and to attach the wildcard cert to their HTTPS listeners. The shared workspace's HTTPS listener itself also consumes module.dns.wildcard_cert_arn directly.

Operating this piece

Cut DNS over from another registrar

  1. Audit the current registrar's record set verbatim — every MX, every TXT string, TTL values, subdomain CNAMEs. Commit the audit before touching Terraform.
  2. Replicate the email-load-bearing records in infra/modules/dns/main.tf. Drop cosmetic website records (apex A, www CNAME) if they're being retired.
  3. terraform apply in infra/environments/shared/ — the zone + email records + ACM cert provision, but the cert stays PENDING_VALIDATION until step 5.
  4. Verify every email record resolves against AWS nameservers directly: dig @ns-XXX.awsdns-XX.com +short MX mythrun.com (and the same for each TXT). Gate the cutover on all of them matching the Squarespace audit.
  5. At the registrar, swap nameservers to the four AWS NS values printed by terraform output name_servers. Propagation is typically 5–60 minutes.
  6. Smoke-test email in both directions once dig +short NS mythrun.com returns AWS NS. SPF, DKIM, and DMARC should all report pass on the inbound headers.

Roll back a broken cutover

  1. Re-point the registrar's NS records back to the previous provider.
  2. Wait out another 5–60 minutes of propagation. Sending MTAs queue during the gap; nothing is lost, but delivery stalls.
  3. Do not destroy the Route 53 zone — leave it in place for the next attempt. Changing a record's TTL and re-applying is cheap; reprovisioning a zone is not.

Add a multi-string TXT record (long SPF, BIMI VMC, rotating DKIM)

  1. Pass the raw value through the same chunking expression used for DKIM: join("\" \"", [for i in range(0, length(x), 255) : substr(x, i, 255)]).
  2. Keep the expression unquoted on the outside — the AWS provider adds the outer double-quotes. An explicit outer wrap produces InvalidCharacterString at apply time.
  3. Verify with dig +short TXT <name>; the output should show each chunk as its own quoted string.

Integration points

The wildcard cert lands on the shared ALB's HTTPS listener; per-env serving infrastructure attaches host-based listener rules and publishes its own A-alias records into this zone. Email flows through the MX records to Google Workspace; that boundary is opaque to Mythrun.

Appendix: inputs & outputs

Inputs

Variable Notes
domain_name Apex domain, no trailing dot. Example: mythrun.com.
dkim_key_rrdata Full DKIM TXT value (v=DKIM1;k=rsa;p=…). Module handles 255-octet chunking internally.

Outputs

Output Shape Notes
zone_id string Route 53 zone ID.
zone_name string Apex domain, no trailing dot.
name_servers list(string) Four AWS nameservers. Informational after the cutover.
wildcard_cert_arn string Sourced from the validation waiter; safe to attach to an ALB listener.

Records managed in this zone

Name Type Purpose
apex MX Five Google Workspace mail servers (priorities 1/5/5/10/10).
apex TXT SPF + Google site verification (one RRSET, two strings).
_dmarc TXT DMARC policy: p=quarantine, rua=dev@.
google._domainkey TXT DKIM public key, multi-string encoded.
ACM-assigned CNAME Wildcard cert DNS-01 validation (one per unique parent).
