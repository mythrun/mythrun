Data

Schemas, repositories, Postgres, and the operator-facing bootstrap path.

Four pages in this section: Schema — the Postgres shape (full table inventory in the schema reference); Migrations — the runner that applies it; Repository layer — the closure-factory seam every read and write flows through; and Bootstrap database — the one-shot ECS task family that creates per-env databases, rotates app passwords, and (staging only) seeds smoke-user credits.

Redis and BullMQ are documented on adjacent pages where their stories actually live: ElastiCache provisioning sits on Infra / Data plane; the BullMQ worker shell and its two queues sit on Runtime / Worker; the realtime channel format and SSE bridge sit on Runtime / Pipeline status.
