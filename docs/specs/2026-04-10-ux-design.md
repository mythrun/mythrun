## 1. Design Philosophy

### Core Aesthetic: Light, Airy, Playful

Mythrun's visual identity is warm, clean, and inviting. It should feel like opening a beautifully illustrated children's book, not entering a dark dungeon.

**Do:**
- Light backgrounds (warm whites, soft creams)
- Soft shadows, things feel like they float
- Gentle transitions — fade in, fade out, breathe
- Pastel accents for color (not neon, not saturated)
- Pixel/voxel decorative elements that feel cartoonish and charming
- Serif font for narrative text (DM prose, world descriptions) — the feeling of a story being read
- Sans-serif for UI elements (buttons, labels, navigation) — clean and functional
- Generous whitespace — every element has room to breathe

**Don't:**
- Dark backgrounds as default (dark mode available as a toggle, not the primary experience)
- Neon borders, glowing accents, cyberpunk-adjacent styling
- The "Claude/ChatGPT dark chat" aesthetic — dark panel, light text, colored borders
- Dense information displays, dashboards, developer tooling aesthetics
- Generic fantasy parchment/leather textures
- Arcade game energy — the pixel elements are decorative, not retro-gaming

**Mood:** Ethereal. Something is being created. A world is being born. The player is participating in something gentle and magical, not conquering something dark and dangerous.

**Accessibility baseline:**
- All animations respect `prefers-reduced-motion` (instant transitions for users with vestibular/motion sensitivity)
- Design system built with CSS custom properties (design tokens) from day one — required for dark mode and future theming
- Font choice toggle in user settings (serif default, sans-serif option, OpenDyslexic option for dyslexic users)
- All colored UI elements verified against WCAG 2.1 AA contrast ratios (4.5:1 for text, 3:1 for large text)

**Visual references** (target aesthetic — "our voxels look like these, not Minecraft"):
- Townscaper (pastel voxels, meditative, no hard edges)
- Monument Valley (isometric, geometric, ethereal)
- Tunic's overworld (soft-lit isometric, storybook feel)
- Old Stripe landing page illustrations (isometric, clean, whimsical but not childish)

### Interaction Philosophy: One Thing at a Time

Inspired by Pokemon game introductions and Apple product setup screens:
- Present one question, one choice, one moment at a time
- The player never sees a form with 10 fields — they see a single prompt that fades in
- After answering, the response fades out and the next prompt fades in
- Progress feels like a conversation, not a checklist
- No visible step indicators ("Step 3 of 7") — the flow feels organic, not procedural

### Dark Mode

Available as a user preference toggle. The dark mode should be a true inversion of the light aesthetic — dark warm grays (not pure black), muted accents, maintaining the same airy feeling. Not a separate design language.

## 2. Landing Page

The landing page sells the *experience* first, with transparent pricing. No feature lists, no screenshots.

### Hero Section

- Light, atmospheric background — a pixel/voxel world gently rotating or assembling itself (reuse the loading animation aesthetic, but as ambient decoration)
- A single line of evocative text fades in. Something like: *"Your story. Your world. Your table."* (final copy TBD)
- Two actions:
  - **"Start your adventure"** — primary button, leads to sign-up
  - **"See it in action"** — secondary, plays a short embedded video or animated demo showing what a real session looks like (DM text streaming in, dice rolling, combat transition)

### Scroll Content (optional, for the curious)

Three brief sections, each with a subtle animation:
1. **"Create a world"** — brief text + animation of a world populating
2. **"Build your character"** — brief text + character creation preview
3. **"Play with friends"** — brief text + multiplayer chat preview

Each section is 1-2 sentences and a visual. No paragraphs, no bullet lists.

### Footer

Minimal: links to terms, privacy policy, and a "Questions?" contact link.

### Pricing Line

A single transparent line below the hero, before the scroll content: *"Sessions start at $X. Your first is free."* Not a pricing table — just trust-building transparency. Pages with visible pricing convert 2-2.5x better than those that hide it.

### What's NOT on the landing page

- Feature comparison tables
- Testimonials (no users yet)
- Technical details ("powered by Claude," etc.)
- App screenshots

## 3. Sign-Up and Sign-In

### Sign-Up

After clicking "Start your adventure," the player sees:

1. A simple choice: **"Continue with Google"** or **"Continue with Discord"** — two buttons, centered on the page. No email/password form. OAuth-only is a deliberate choice: Google and Discord require phone verification, which prevents free-tier abuse via temp email services. The D&D audience is 90%+ on Discord.
2. OAuth flow redirects to Google/Discord, returns to Mythrun.
3. On first sign-in, a gentle onboarding moment: *"What should we call you?"* — single text input for display name, with the ethereal fade-in style. Pre-filled from the OAuth provider's display name if available.
4. After setting display name, the player lands on the Home Screen.

### Sign-In (returning users)

Same two buttons. OAuth recognizes the returning user. Redirects straight to the Home Screen.

### No Onboarding Tutorial

No tooltips, no "take a tour," no walkthrough modals. The flows themselves are simple enough to be self-explanatory. If a player needs a tutorial to use the product, the product is too complex.

## 4. Home Screen (Campaign Hub)

The player's home base between sessions. Clean, minimal, campaign-focused.

### Layout

**Header:** Mythrun logo (small, unobtrusive), player display name, session credits display ("5 sessions" with a subtle "+" icon to buy more), settings gear icon.

**Main content:** Campaign cards in a responsive grid (1-3 columns depending on screen width).

**Each campaign card shows:**
- Campaign name (large, prominent)
- World name (smaller, below — if from a shared world, show "by [Creator]")
- Party members (small avatar circles or initials, max 5)
- Session count: "4 sessions played"
- Status indicator:
  - "Ready to play" (green dot) — world + characters done, credits available
  - "Creating world..." (animated) — pipeline running
  - "Waiting for players" — not all invitees have created characters
  - "Create your character" — you've joined but haven't made a character yet
- Last played: "2 days ago"

**Empty state (new user):** No cards. Instead, a centered prompt in the ethereal style: *"Every adventure begins with a world."* and a **"Create a campaign"** button.

**Invite banner:** If the player has a pending invite (arrived via invite link), a gentle banner appears at the top: *"You've been invited to join [Campaign Name]"* with **Accept** / **Decline** buttons. Accepting flows directly into character creation for that campaign.

### Top-Level Actions

- **"New Campaign"** button — prominent, leads to the Campaign Creation flow
- Campaign cards are clickable — leads to the campaign's play screen or pre-play state (character creation, waiting for players, etc.)

## 5. Campaign Creation Flow

This is the "Pokemon intro" experience. One question at a time, gentle transitions, the feeling of something being born.

### Flow

**Step 1: "What kind of world?"**
A single text prompt fades in: *"Describe the world you want to play in. A sentence is enough. A paragraph is welcome."*

A large, centered text area. No character limit shown. Placeholder text in light gray: *"A dying kingdom where the sun hasn't risen in a hundred years..."*

A **"Create"** button below. On click, the text fades out.

**Step 2: World generation begins**
Transition to the World Generation Experience (section 6). The player watches their world come to life.

**Step 3: "Where do you begin?"**
After world gen completes, the starting locations fade in one at a time. Each is a card with:
- Location name
- 1-2 sentence hook ("A salt-crusted port town where every merchant owes someone a debt")

The player selects one. The others fade away.

**Step 4: Character creation**
Flows directly into the Character Creation flow (section 7).

**Step 5: Invite friends (optional)**
After character creation: *"Invite your party?"* with a **"Share invite link"** button and a **"Play solo"** option. The invite link is a short URL that works whether the recipient has an account or not.

**Step 6: Ready to play**
If solo: flows directly to the play session.
If multiplayer: returns to the Home Screen. The campaign card shows "Waiting for players." The session starts when the owner clicks "Start session" (requires all invitees to have created characters, or the owner can start without them).

### What's NOT in the creation flow

- World name selection (the LLM generates this during world gen — the player sees it revealed)
- Genre/theme dropdowns or tag selectors — the freeform text prompt handles everything
- Step indicators, progress bars, or numbered stages
- Configuration options, difficulty settings, house rules

## 6. World Generation Experience

This is NOT a loading screen. It's a creation experience. The player watches their world come into existence.

### The Visual

A **pixel/voxel globe** centered on the screen. As the pipeline stages run behind the scenes:

- The globe starts empty — a featureless sphere
- **Concept intake completes:** The world's name fades in above the globe. The globe begins to develop terrain — mountain ranges push up, coastlines form, forests spread. These are generic voxel animations, not literally accurate to the generated geography.
- **World and factions completes:** Small banner-like icons appear around the globe representing factions. Brief text snippets fade in and out: the world's tone, era, a key tension. Just enough to tease, not to info-dump.
- **Locations and NPCs completes:** Small glowing dots appear on the globe — cities, settlements, points of interest. Each dot might briefly show a name label before fading.
- **Starting situation completes:** The globe gently zooms into one region. The "Where do you begin?" prompt fades in.

### Timing

World gen takes 2-5 minutes (5 Opus calls in sequence). The animations should be paced to fill this time naturally. If the pipeline finishes faster than expected, the animations can accelerate. If slower, they can linger on each phase.

### Behind the Scenes

The client polls or receives SSE updates for pipeline stage completion. Each stage transition triggers the next animation phase. The mapping is:
- `concept_intake` -> globe + name reveal
- `world_and_factions` -> terrain + faction icons
- `locations_and_npcs` -> city dots + name labels
- `starting_situation` -> zoom + location prompt

### Text Alongside

Minimal text appears during generation — snippets from the generated world that tease what's being created:
- The campaign name (after concept intake)
- The tone: *"A paranoid political thriller set in a crumbling empire"*
- 1-2 key tensions: *"The old king's heirs are missing. The merchant guilds sense opportunity."*

These fade in and out gently. The player reads them while watching the globe animate. They build anticipation without overwhelming.

### No Progress Bars

No percentage indicators. No "Stage 3 of 5." No ETA. The experience is the animation, not the tracking.

## 7. Character Creation Flow

Same ethereal, one-question-at-a-time pacing as campaign creation.

### Two Paths

The player chooses how they want to create their character:

- **"Tell us who you are"** — freeform text path (for theater-kid players with a vivid concept)
- **"Build your character"** — guided builder path (for players who want to choose class, subclass, features)

Both paths use the same ethereal, one-at-a-time pacing. Both end at the same character sheet reveal.

### Path A: Freeform

**Step 1: "Who are you?"**
*"Tell us about your character. Who are they? What brought them here?"*

Single text area. The player writes a character concept — anything from "a grumpy dwarf blacksmith" to three paragraphs of backstory.

### Path B: Guided Builder

Same ethereal pacing — one choice fades in at a time, not a form:

1. *"What is your calling?"* — Class selection. Each class presented as a card with a brief evocative description (not mechanical stats). Player selects one, others fade.
2. *"How do you practice it?"* — Subclass selection (if applicable at level 1). Same card format.
3. *"Where do you come from?"* — Species + background. Brief descriptions, one selection each.
4. *"Anything else the world should know?"* — Optional freeform text for backstory, personality, or specific requests ("I want to know the tavern owner personally"). Can be skipped.

The LLM fills in ability scores, equipment, spell selection, and world integration. The player makes the identity choices; the system handles the mechanical details.

### Both Paths: Waiting (with animation)

**Step 2: Waiting (with animation)**
The LLM processes the character concept, generates the character sheet, and integrates the character into the world. During this time:

- A character "silhouette" animation — a voxel figure that gradually fills in with detail (armor, weapons, features) as the pipeline progresses
- Brief text reveals: character name (if the LLM chose one), class, species — fading in one at a time
- The feeling: your character is being born into this world

**Step 3: "Meet your character"**
The completed character is revealed. A clean, visual character sheet:
- Name, class, species, background — large, prominent
- Ability scores in a visual layout (not a table)
- Key features and equipment highlighted
- A prose paragraph: the character's connection to the starting location

**Step 4: Confirm or revise**
*"Is this who you want to be?"*
- **"This is me"** — accept and continue
- **"Tell me more"** — expand the character sheet with full details (skills, all equipment, spells)
- **"Start over"** — return to the concept prompt (costs another LLM call, acceptable)

### For Multiplayer (Joining a Campaign)

When a player accepts an invite and joins an existing campaign, they see a briefer version:
- The world already exists — show a brief world summary (name, tone, their starting location)
- Flow directly into "Who are you?" character creation
- After character creation, return to Home Screen. The campaign card updates to show them as a party member.

## 8. Invite and Party Assembly

### Creating an Invite

After the campaign owner finishes their character (or from the campaign card later):
- **"Invite friends"** button generates a shareable link
- The link is a short URL (e.g., `mythrun.com/join/AbCdEf`)
- A copy button and a "Share" button (mobile share sheet on supported devices)
- The link can be shared via Discord, text, email — whatever

### Receiving an Invite

- Recipient clicks the link
- If not signed in: redirected to sign-up, then back to the invite
- If signed in: sees the invite banner on the Home Screen (section 4)
- Accepting flows into character creation for that campaign's world

### Party Assembly

The campaign owner sees their campaign card update in real-time as players join:
- "Waiting for 2 players" -> player joins -> "Waiting for 1 player"
- Each player's avatar/name appears on the card as they complete character creation
- The owner can start the session at any time (even if not all invitees have joined — late joiners can create characters and join mid-campaign later)

### No Lobbies, No Matchmaking

Players find each other through invite links shared outside the app. There is no in-app player discovery, public campaign listing, or matchmaking system at launch. The world marketplace (future feature) will be the first discovery mechanism.

## 9. The Play Session

### Starting a Session

From the campaign card, the owner clicks **"Start session"**. All party members who are currently online get a notification (in-app — a banner or modal). Players who are offline see the active session when they next open the app.

During session prep generation (1-2 minutes), the players see a loading experience similar to world gen — atmospheric, not a spinner. Brief text: *"The DM is preparing tonight's session..."* with subtle animation.

### The Play Screen

**Layout:** Two-panel with a sidebar.

**Main panel (left, ~70% width): The chat.**
- Discord-like group chat interface
- Light background, clean typography
- DM messages in serif font, slightly larger — the feeling of a book being read
- Player messages in sans-serif, smaller — casual, chat-like
- Clear visual distinction between DM and player messages (not just name labels — different background tints, typography)
- Entity highlighting: recognized entity names (NPCs, locations, factions) have a subtle underline — same treatment for all types. On hover, the underline shifts to the entity-type color and the name becomes clickable. On click, a popover card appears (see section 12). This preserves reading flow — the inline treatment is barely visible, not a colored hyperlink.
- Typing indicators: "[Player name] is typing..." shown below the latest message
- Input at the bottom: text field + send button + a prominent **@DM** button. No special formatting tools.
- The `@DM` button is the **primary** way to invoke the DM. Clicking it (or typing `@DM`) explicitly addresses the DM with the player's message. The DM also auto-triggers as a safety net for: action declarations that skip resolution ("I kill the orc and loot his body"), and idle timeouts in multiplayer. In solo play, the DM triggers after every player input.
- "DM is thinking..." indicator appears instantly when the DM is triggered (before the classifier runs, not after)

**Sidebar (right, ~30% width): Reference tools.**
Three tabs (icons, not text labels to save space):
1. **World Wiki** — browsable world state, organized by location/NPC/faction. Only shows information the player's character would know (public facts, delivered facts). Updated in real-time as the Scribe extracts new information during play.
2. **Relationship Graph** — the interactive entity graph, filtered to the player's knowledge. Clickable nodes open the wiki entry.
3. **Character Sheet** — the player's own character: stats, skills, features, equipment, spells. Updated if combat changes HP, conditions, etc.

The sidebar defaults to **open** — one of the first things a player should do is explore the world to get their bearings. It is collapsible via a toggle button. On mobile (if supported), it slides in as a drawer. Clicking an entity highlight in the chat opens the sidebar to the relevant wiki entry if the sidebar is collapsed.

### Dice Rolls and Skill Checks

The existing prototype flow, refined:

1. The DM determines a skill check is needed (via the `roll_skill_check` tool call)
2. A dialogue appears in the chat: a "roll card" showing the skill name and context
3. The player clicks **"Roll"**
4. A dice animation plays (the result is predetermined server-side)
5. The result reveals: d20 value, modifier, total, DC, outcome tier (success/fail/great success)
6. The player clicks **"Continue"**
7. The DM narrates the outcome in the chat

For non-skill dice rolls (`roll_dice`): same flow but simpler — just the dice animation and result.

### Session End

The DM winds down the session narratively (triggered by token budget at 80-90%, or by the owner clicking "End session").

After the session ends:
- The DM's final message is a session recap (2-4 sentences)
- A gentle transition card: *"Session complete"* with emerging threads and a hint of what's next
- The player returns to the Home Screen. The campaign card updates with the new session count.

## 10. Combat Mode

### Transition

When the DM triggers combat:

1. **"Roll initiative" beat.** A brief (~1-2 second) full-screen transition. Not a cinematic production — a *moment*. At a real D&D table, the DM pauses, looks around, and says "Roll initiative." Players cheer or groan. That's the UX beat: a pause, a shift in atmosphere, and then the combat UI appears. The transition plays every time combat starts (not skippable, not shortened for repeat encounters) because it's short enough to never feel tedious.

2. The screen reorganizes into the **combat layout.**

### Combat Layout

**Main area (~75% of screen): Voxel battlemap.**
- Isometric view of the AI-generated battlefield
- Voxel terrain: floors, walls, obstacles, elevation — low-detail, Minecraft-aesthetic but cleaner
- Character tokens on the map (distinct voxel figures per combatant)
- Camera: pan, zoom, rotate (mouse/touch)

**Top bar: Initiative tracker.**
- Horizontal strip showing turn order — small character icons/names in initiative sequence
- Current turn highlighted
- HP bars visible for all combatants (players see exact HP for allies, approximate for enemies — "healthy/bloodied/critical")

**Bottom bar: Action palette (on your turn).**
- Available actions based on your character's action economy
- Move (click on map to set destination — path preview, movement cost, OA warnings)
- Attack (click enemy — shows range, hit probability)
- Cast spell (opens spell list filtered to available slots + prepared spells)
- Other actions: Dodge, Dash, Disengage, Help, Hide, Ready, Use Item
- Grayed-out actions you've already used this turn
- "End Turn" button

**Side panel (~25%): Combat chat.**
- The DM narrates combat events here (1-2 sentences per action)
- Players can type questions/requests: "Does the goblin look injured?" "Can I throw this table?"
- The DM responds with rulings that may affect the tactical state
- This is a reduced version of the main chat — no world wiki, no character sheet, just narrative and questions
- **Context bridge:** The combat chat begins with the last 3-5 DM messages from the main chat (visually dimmed, separated by a divider labeled "Before combat"). This gives the player context about how they got into this fight without requiring them to remember.

### Combat to Narrative Transition

When combat ends:
1. Reverse transition animation — combat UI disassembles, chat returns
2. The DM narrates the aftermath in the chat (using the CombatSummary)
3. Players are back in the normal play session

## 11. Billing and Credits

### Philosophy

Billing is a door you pass through, not a wall you hit. The player should never feel blocked — just gently guided to purchase. Billing UI is clean and minimal, matching the overall aesthetic.

### When Billing Appears

**Moment 1: After free trial ends (highest conversion moment)**
- The free trial ends with either a **hook** (satisfying micro-conclusion that reveals a bigger mystery) or a **cliffhanger** (mid-action cutoff) — both approaches should be A/B tested to determine which converts better. A hook provides resolution + curiosity; a cliffhanger provides urgency. D&D players may react differently to each.
- The chat fades to a warm prompt: *"Your story continues."*
- Below: subscription and pack options (see Pricing Display below)
- A "Maybe later" option that returns to the Home Screen (no pressure)

**Moment 2: When credits run out**
- The owner tries to start a session with zero credits
- Instead of an error, a gentle prompt: *"You're out of sessions."*
- Session pack options below
- One-click purchase via Stripe Checkout

**Moment 3: Account settings**
- A "Sessions & Billing" section showing:
  - Current credit balance
  - Purchase history (date, pack size, amount)
  - "Buy more" button
  - "Manage payment method" link (Stripe Customer Portal)

**Moment 4: Campaign card (passive indicator)**
- The campaign card shows the owner's remaining credits subtly
- When low (1-2), the indicator turns amber — a nudge, not a block

### Pricing Display

**Subscriptions (primary offer):**
- Three monthly tiers presented in order of volume:
  - "Wayfarer — 4 sessions + 1 world / month — $X/mo"
  - "Sojourner — 8 sessions + 2 worlds / month — $Y/mo"
  - "Mythwright — 16 sessions + 4 worlds / month — $Z/mo"
- Auto-renewing via Stripe. Credits granted monthly. Unused tier credits expire at the end of the billing period (no rollover).
- "Subscribe" button opens Stripe Checkout in subscription mode.

**À-la-carte SKUs (for irregular players):**
- Shown below the subscriptions: "Or pay as you go"
- Two SKUs, sold one-at-a-time:
  - "Session — $X" (1 session credit)
  - "World — $Y" (1 session credit + 1 world credit)
- No "best value" labels; quantities are user-chosen at checkout.
- One-click "Buy" opens Stripe Checkout in payment mode. À-la-carte credits never expire.
- No custom payment form — Stripe handles the entire payment page.

### Campaign Ownership Transfer

If a campaign owner stops paying or wants to hand off hosting duties, any campaign member can be promoted to owner:
- Owner can transfer via campaign settings: "Transfer ownership to [Player Name]"
- If the owner's account is inactive for 30+ days, members see an option: "Adopt this campaign" (become the new owner and assume payment responsibility)

### Credit Display

- In the header: a small icon + number ("5 sessions remaining")
- Clicking opens a dropdown with balance details and a "Buy more" link
- The "+" icon next to the credit count is always available as a quick purchase shortcut

## 12. Entity Highlighting and World Knowledge

### In-Chat Highlighting

When the DM mentions entities that exist in the world state (NPCs, locations, factions):
- The entity name is rendered with a **subtle underline** — the same visual treatment for all entity types. The underline is barely visible, not a colored hyperlink. This preserves the immersive reading experience (research on hypertext reading shows that colored inline links increase cognitive load and reduce comprehension).
- **On hover:** the underline shifts to an entity-type color (NPC = blue, location = amber, faction = green) and the cursor changes to indicate clickability. This is the discovery moment — the player finds interactive elements when they want them, not when the system imposes them.
- Entity-type colors use a secondary differentiator beyond color for accessibility (8% of men have color vision deficiency): NPC names are italic when hovered, location names show a small pin icon, faction names show a small shield icon.

### Click Behavior

Clicking a highlighted entity name opens a **popover card** anchored to the clicked text:
- Entity name + type badge (NPC / Location / Faction)
- Prose kernel (the 2-3 paragraph description)
- Key public facts the character knows
- Relationships to other entities the character knows about
- A "View in Wiki" link to open the full entry in the sidebar

### Knowledge Filtering

The player only sees information their character would know:
- **Public facts**: always visible
- **Delivered facts** (narrative_status = 'delivered'): visible once the DM has revealed them in play
- **Private/secret facts**: never visible to the player
- The wiki, graph, and entity popovers are all filtered through the same access level rules
- The entity graph only shows entities the character has encountered or heard about

### World Wiki (Sidebar Tab)

Organized as a browsable reference:
- **Locations**: grouped by region hierarchy (region > settlement > specific place)
- **NPCs**: grouped by location or faction affiliation
- **Factions**: flat list
- Each entry shows: name, prose kernel excerpt, key facts
- Search bar at the top for quick lookup
- Entries are added/updated in real-time as the Scribe processes DM responses during play

## 13. Loading Philosophy

**Loading is never a blank screen with a spinner.** Every wait state has a purposeful visual experience.

### Loading Animations by Context

| Context | Duration | Animation |
|---------|----------|-----------|
| World generation | 2-5 min | Voxel globe building (section 6) |
| Character creation | 30-90s | Character silhouette filling in |
| Session prep | 1-2 min | Atmospheric: "The DM is preparing..." with subtle world animation |
| DM thinking (in-session) | 3-15s | "DM is thinking..." text indicator (subtle, in-chat) |
| Combat map generation | 10-30s | Voxel blocks assembling into the battlefield |
| Page transitions | <1s | Fade/slide transitions — no flash of white/unstyled content |

### Pixel/Voxel Animation Style

All loading animations share a consistent aesthetic:
- Low-poly voxel elements that assemble, grow, or populate
- Gentle, smooth motion — nothing bounces or shakes
- Pastel color palette matching the overall design language
- No progress percentages or ETAs — the animation itself communicates "something is happening"
- If the backend finishes faster than the animation expects, the animation gracefully accelerates to completion (no jarring skip)
- All animations respect `prefers-reduced-motion` — replace with instant appearance for motion-sensitive users

### Implementation Tiers

**Target (attempt first):** 3D voxel animations using Three.js — the globe, character silhouette, battlefield assembly. AI tooling may accelerate development significantly.

**Fallback (if 3D timeline slips):** Elegant 2D illustrations with CSS animations. Branded, charming, effective (Duolingo-style). Same pastel/voxel aesthetic rendered as flat art with subtle motion (parallax layers, fade-in sequences). The brand identity is preserved; the dimensionality is reduced.

## 14. API Surface Implications

The UX design drives specific backend API requirements. This section documents what the backend must serve to support the player flows described above.

### Campaign Creation

- `POST /api/worlds` — create a new world from a concept (triggers world gen pipeline)
- `GET /api/worlds/:id/status` — SSE or polling for pipeline stage completion (drives the globe animation phases)
- `GET /api/worlds/:id/preview` — returns the generated world name, tone, era, key tensions (for the text snippets during generation)
- `GET /api/worlds/:id/starting-locations` — returns the location hooks after world gen completes

### Character Creation

- `POST /api/campaigns/:id/characters` — submit character concept + starting location (triggers character creation pipeline)
- `GET /api/campaigns/:id/characters/:charId/status` — pipeline progress for character gen
- `GET /api/campaigns/:id/characters/:charId` — completed character sheet
- `PUT /api/campaigns/:id/characters/:charId/confirm` — player confirms the character
- `DELETE /api/campaigns/:id/characters/:charId` — player starts over

### Campaign Management

- `GET /api/campaigns` — list the player's campaigns (with status, party members, session count)
- `POST /api/campaigns` — create a campaign in a world (may fork a shared world)
- `POST /api/campaigns/:id/invites` — generate an invite code/link
- `POST /api/invites/:code/accept` — accept an invite (joins the campaign)

### Play Session

- `POST /api/sessions/:campaignId/start` — start a new session (triggers session prep if needed)
- `GET /api/sessions/:campaignId/prep-status` — SSE for session prep generation progress
- `POST /api/ws/ticket` — get a single-use WebSocket upgrade ticket
- WebSocket protocol as defined in the architecture overview spec

### World Knowledge (Sidebar)

- `GET /api/campaigns/:id/knowledge` — returns all entities, facts, and relationships the player's character knows about (filtered by access level + narrative status)
- `GET /api/campaigns/:id/knowledge/graph` — returns the entity graph data (nodes + edges) filtered to character knowledge
- This data is updated in real-time via WebSocket `scribe_result` messages — the client updates the wiki/graph locally without re-fetching

### Entity Highlighting

- Entity highlighting is a client-side operation: the client maintains a local cache of known entity names (from the knowledge API) and does substring matching against DM text to highlight recognized names
- No additional API needed — the knowledge endpoint provides the entity name list

### Billing

- `GET /api/billing/credits` — current credit balance (sum of active ledger entries)
- `POST /api/billing/checkout` — create a Stripe checkout session for a pack or subscription
- `GET /api/billing/portal` — get a Stripe customer portal URL (manage subscription, payment method)
- `GET /api/billing/history` — purchase history

### Session Recaps

- `GET /api/sessions/:sessionId/recap` — returns a beautifully formatted session recap (already generated by post-session analysis). The recap page is shareable — a public URL that works without authentication, linking back to Mythrun. No "Share to Facebook!" buttons — just a clean page the player can copy the link to and share however they want. Provides organic growth without feeling like a marketing ploy.

### Campaign Management (additions)

- `POST /api/campaigns/:id/transfer` — transfer campaign ownership to another member
- `GET /api/campaigns/:id/transfer-request` — check if an ownership transfer is available (owner inactive 30+ days)

### User Settings

- `GET /api/users/me` — current user profile
- `PUT /api/users/me` — update display name, preferences (dark mode, font choice)
- `DELETE /api/users/me` — account deletion (cascading, with 30-day soft delete)
